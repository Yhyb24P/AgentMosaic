AgentMosaic

Run heterogeneous coding agents as one durable team.

A high-reasoning Lead plans and reviews. Coding agents and local workers execute. Results and artifacts flow back automatically.

No manual copy/paste between Agents.

Stop being the transport between Agents

Reasoning is the scarce part. Moving text between two Agents by hand is not, so AgentMosaic makes that part automatic.

Manual workflow

  • Reasoning Agent plans
  • You copy instructions
  • Coding Agent executes
  • You copy results back
  • Reasoning Agent reviews
  • repeat

AgentMosaic

  • One objective
  • Lead delegates
  • Workers execute
  • Results/artifacts return
  • Lead follows up or synthesizes
  • Durable result

How the team works

One objective goes in. The Lead reads it, plans the work, and decides what can be delegated. Each delegated task is scheduled to an Agent whose runtime fits the job — a coding Agent over ACP, or a deterministic worker. When a task finishes, its result and any artifacts it produced are written to the durable board and handed back to the Lead. The Lead then reviews what came back and either delegates a follow-up, asks for a correction, or synthesizes everything into one final answer. That answer, together with the exact task and artifact references it depends on, is persisted. Nothing depends on a chat window staying open, and no step requires you to move text between Agents by hand.

Deeper implementation detail lives in the documentation.

Durable by design

Four properties decide whether a multi-Agent run is worth trusting.

Heterogeneous team

Each Agent keeps its own runtime, model and provider boundary. AgentMosaic never pins you to one vendor.

Automatic result flow

A delegated result and its artifacts return to the Lead without anyone re-typing them.

Durable state

Task, result and artifact state is kept in project-local durable state, not in transient chat history.

Resume instead of restart

After an interruption the run picks up from persisted state instead of blindly redoing finished work.

Quickstart

  1. Install the am command.
  2. Initialize project state in your repository.
  3. Register exactly one reasoner as the Lead and one worker.
  4. Check readiness, then run one objective.
Shell 
am init

am agent add lead \
  --role reasoner \
  --adapter codex-app-server -- codex

am agent add worker \
  --role worker \
  --adapter acp -- qwen --acp

am doctor

am run "implement the task, verify it, and summarize the result"

am init writes project-local durable state to .agentmosaic/state.db. Anything after -- is launch argv that AgentMosaic stores and executes unchanged, so credentials never go there.
