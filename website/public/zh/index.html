AgentMosaic

把异构 coding Agent 作为一个持久化团队来运行。

高推理能力的 Lead 负责规划与评审。 coding Agent 与本地 worker 负责执行。 结果与 artifact 自动回流。

无需在 Agent 之间人工复制粘贴。

不再人工搬运 Agent 之间的上下文

真正稀缺的是推理。在两个 Agent 之间手工转移文本不是，所以这部分交给 AgentMosaic 自动完成。

手工流程

  • 推理 Agent 做规划
  • 你把指令复制过去
  • coding Agent 执行
  • 你把结果复制回来
  • 推理 Agent 评审
  • 重复

AgentMosaic

  • 一个目标
  • Lead 委派
  • worker 执行
  • 结果与 artifact 回流
  • Lead 跟进或综合
  • 持久化结果

工作原理

一个目标进入。Lead 读取目标，做出规划，并判断哪些部分可以委派出去。每个被委派的任务会交给运行环境合适的 Agent —— 通过 ACP 接入的 coding Agent，或确定性 worker。任务结束后，它的结果与产生的 artifact 会被写入持久化 board，并交回 Lead。Lead 查看回传内容，然后决定继续委派、要求修正，还是把全部结果综合成一个最终答案。这个答案连同它依赖的任务与 artifact 引用一起被持久化。整个过程不依赖某个对话窗口一直开着，也不需要你手工在 Agent 之间搬运文本。

更深入的实现细节见文档。

持久化设计

一次多 Agent 运行是否值得信任，取决于四个性质。

异构团队

每个 Agent 保留自己的 runtime、模型和 provider 边界，AgentMosaic 不把你锁在单一厂商上。

自动回流

被委派任务的结果与其 artifact 会回到 Lead，不需要任何人重新录入。

持久化状态

任务、结果与 artifact 状态保存在项目本地的持久化状态中，而不是临时对话历史里。

恢复而非重跑

中断之后，运行从持久化状态继续，而不是无条件重做已经完成的工作。

接入你的 Agent

注册你已经在用的 runtime，然后让团队在它们之间调度工作。

Lead

Codex
通过 codex-app-server 接入，当前作为参考的高推理 Lead。

Worker

ACP 兼容的 coding runtime
这是 worker 边界。本地模型也经由它自己的 ACP runtime 接入。

AgentMosaic 负责

  • 角色
  • 委派
  • 任务状态
  • 结果与 artifact 回流
  • 恢复

外部 runtime 负责

  • 登录
  • 凭据
  • provider
  • 模型
  • launcher profile

快速开始

  1. 安装 am 命令。
  2. 在你的仓库里初始化项目状态。
  3. 注册恰好一个 reasoner 作为 Lead，以及一个 worker。
  4. 检查就绪状态，然后运行一个目标。
Shell 
am init

am agent add lead \
  --role reasoner \
  --adapter codex-app-server -- codex

am agent add worker \
  --role worker \
  --adapter acp -- qwen --acp

am doctor

am run "implement the task, verify it, and summarize the result"

am init 会创建项目本地持久化状态。-- 之后的内容是 launch argv，AgentMosaic 只原样存储与执行，因此凭据不应写在那里。

运行结束后，am status、am final、am artifact 和 am tui 会就地读取持久化结果，不需要数据库路径；加 --json 可得到单个机器可读对象。
